## 场景

1. **principles 五条原则**（6 句）：热钱包 → 攻击者的资金流与告警铃；绿色闸门“止血”切进去，下方两条泳道（止血从 T+0 开始，调查晚开始）；审批链被打叉、值班人员直连动作；误停 / 漏停两根代价条；内部 IM 里的红眼睛 → 独立应急渠道；止血与证据两条并行泳道 + “为了清理重装机器”打叉。
2. **timeline 第一个小时到第一周**（5 句）：T+0、10 分钟、60 分钟、24 小时、7 天的轴（刻度示意），每句点亮一段，下面长出该段的目标、必须完成、负责人，前一段变暗。
3. **layers 止损分层**（8 句）：左侧五层堆叠逐层点亮。用户 → 网关 → 签名服务 → 链上，攻击者从内网绕过网关；Bitget 约 2.4 亿；停签开关拨动、出链打叉、“< 5 分钟”验收条；协议合约外流撞阈值 → 自动暂停；服务器关停但链上委托照常提币 → 演练清除；攻击者地址 10 分钟内发给三方，时间轴上标出 10–20 分钟换币窗口和“复盘完才通知 · 已错过”。
4. **command 事件指挥与联络**（6 句）：中心“事件指挥”节点 → 六个角色环 → 总线连出外部联络清单；SEAL 911 工单流程，自称成员私信时的暗语三步，转介商业追踪公司。
5. **playbook 六类场景的前三步**（7 句）：左侧 A–F 六个场景，右侧先放一张空卡模板（三步 + 不要做），之后每句点亮一类并填入前三步、不要做、对应案例。
6. **after 证据、公告与恢复**（7 句）：停签标记前后两份日志流向“不受影响的存储”，终端先镜像再隔离，事件日志面板；首次公告“说 / 不说”两栏，冻结≠追回、补足≠没有损失；平台入口未堵、攻击者再来一次 + 恢复前确认清单，三级台阶分阶段恢复；复盘闭环。

合计 6 场景 / 39 句。
