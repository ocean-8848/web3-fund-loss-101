## 场景

1. metrics（6 句）裂开的 D02 盾牌，两侧长出“发现失效”的眼睛和“账实相符”的天平，下方是“定期证明”的对勾 → 收成时间线“异常开始 → 发现 → 停住”，两段括号分别填目标值 → 底部“日志 →”一排其余指标。
2. logs（6 句）上排攻击阶段全是问号；下排日志源逐个亮起，光束照亮对应阶段；签名与策略层加粗“永久保留”；所有日志汇入安全数据平台，失守服务器的删除被挡住；最后 EDR 断开，入口与立足重新变成问号。
3. rules（6 句）上排五个阶段，指针逐个移动；下方“信号 → 规则示例 → 自动动作”三框按阶段换内容，底部注明出现在哪些案件；已讲完的阶段打勾。
4. recon（7 句）区块链条 → 单个热钱包 10 分钟流出柱状图，尖峰冲过阈值 → 自动停签；加基线带、拆成主 / 次告警 → 三账三个账本两两核对，下方提现对订单，找不到订单 → 拒绝并告警 → 链上余额条缩短，出现差额 → “钱少了 = 一定有差额”。
5. change（4 句）时间轴上一段变更窗口，窗口内转账混着一笔红色异常 → 每笔挂上变更单号，无单号的被拒 → 下方补丁流水线，括出 ≤ 72 小时 → 窗口里挂出“系统维护中”公告，异常转出升最高级别。
6. sev（5 句）两名值班与停签按钮 → 右侧 SEV1–SEV4 四级逐行出现（情形、时限、预先授权动作）→ 左侧换成天平：误停（时钟）轻、漏停（全部余额）重。
7. drill（6 句）一年 12 个月的演练日历：每月停签演练、每季度推演、每年红队、同业复盘逐行出现，右侧是通过标准 → 若干次演练标出缺口，红箭头汇入“D02 控制清单”，绿箭头回到日历。

## 没上 slides 的点

- §2 各日志源的“必须采集”字段与保留期（≥ 1 年 / 永久 / 按合规要求）：只上了签名服务与策略层的“永久保留”，其余属细节表格。
- §3 各阶段的“检测信号”原文较长，屏幕上做了压缩（如入口只写“高薪邀约、外部面试作业”，省略“开源贡献者邀请运行项目”和邮件网关规则）。
- §4 链上监控表的其余对象（合约权限与实现变化、EIP-7702 委托、大额 approve、桥铸造量超过锁定量、价格源偏离、退役地址转入告警）：rules 场景的“链上执行”一行已覆盖实现地址与委托变化，其余省略以控制页数。SEAL 的“两家独立监控方”一条也省略。
- §4 三账对账的“差额阈值”与“超阈值动作”（停签该钱包人工核对 / 暂停提现联合核对）：省略，只上了频率和“找不到订单拒绝并告警”。
- §5 P0 的“迁移前先把旧钱包余额归集到冷钱包”、P1“升级前主网分叉回放与不变量断言（Nomad）”：页数所限省略；后者在 D02 合约部分更合适。
- §6 SEV 各级“通知谁”一列、“每次 SEV1 / SEV2 写复盘”：省略。
- §7 订阅官方通报（TraderTraitor）、事先加入行业应急渠道、共享攻击指标：只上了“读同业复盘”一条；应急渠道在 D04 / D05 讲。
- §8 社会工程演练、合约暂停演练、密钥恢复演练三行：日历只放了停签演练、桌面推演、红队三项，避免变成表格。
- §9 参考：不额外引用。
